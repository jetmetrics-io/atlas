# Атлас: База, сборка, деплой

Инструкция для обеих машин — Дмитрия и Марии. Всё, что нужно знать, чтобы
работать с Атласом и не наступить на то, на что мы уже наступили.

> **Коротко.** Правда — в `db/atlas.sql`. Всё остальное из неё собирается:
> `npm run db` → база, `npm run gen` → выгрузка, `npm run deploy` → бой.
> Руками выгрузку не правят никогда.

---

## 1. Как устроен конвейер

```
db/atlas.sql ──restore──> db/atlas.db ──build_app──> public/data/*.json ──vite──> dist/ ──deploy──> бакет
   (в git)                 (рабочая)                   (выгрузка)                            storage.yandexcloud.net
```

| Что | Где лежит | В git? |
|---|---|---|
| **Дамп Базы — источник правды** | `db/atlas.sql` | ✅ да |
| Миграции (история правок) | `db/migrations/` | ✅ да |
| Рабочая копия Базы | `db/atlas.db` | ❌ собирается из дампа |
| Выгрузка приложения | `public/data/*.json` | ❌ собирается из Базы |
| Сборка для выкладки | `dist/` | ❌ |
| Слепок боя для отката | `.rollback/` | ❌ |
| Ключи бакета | `app/.deploy.env` | ❌ **никогда** |

**Почему дамп, а не сам файл базы.** `.db` — двоичный: `git diff` по нему
показывает «файл изменился», а при слиянии одна копия молча затирает другую.
Текстовый дамп показывает, какая метрика поменялась, и честно даёт конфликт,
если двое правили Базу одновременно.

## 2. Первый запуск на новой машине

```sh
git clone https://github.com/jetmetrics-io/atlas.git app && cd app
npm ci
npm run db          # db/atlas.sql → db/atlas.db
npm run gen         # База → public/data/*.json
npx vite --port 5179
```

Открыть `localhost:5179`. Вид оплатившего — `localhost:5179/?paid=1`
(отмычка работает только на локальной машине).

## 3. Каждый рабочий день

### Начало: подтянуть чужое

```sh
git pull
npm run db          # пересобрать базу из свежего дампа
npm run gen         # пересобрать выгрузку
npm run pull        # ← что сейчас в бою и чем отличается от моего
```

`npm run pull` ничего не меняет. Он отвечает на вопрос «бой ушёл вперёд?» —
это единственный способ узнать, не выложил ли кто-то своё, пока вы работали.

### Правка Атласа

⛔ **Правится База, а не выгрузка.** Не `public/data/*.json`, не файлы правок
поверх — только База. Всё остальное пересобирается.

Способ внести правку — миграция в `db/migrations/`, по образцу соседних файлов:
у каждой есть `primenit()`, `proverit()` и ключ `--check`, каждая делает бэкап
перед работой и переживает повторный запуск.

```sh
python3 db/migrations/005_moya_pravka.py db/atlas.db        # применить
python3 db/migrations/005_moya_pravka.py db/atlas.db --check # только проверить
npm run db:check                                            # целостность Базы
npm run gen                                                 # пересобрать выгрузку
```

Мелкую разовую правку можно сделать и прямо в Базе (`sqlite3 db/atlas.db`),
но тогда её не будет видно в истории. Миграция — способ объяснить, **почему**
правка такая; через месяц это единственное, что останется.

### Конец: уложить своё

```sh
npm run db:dump     # db/atlas.db → db/atlas.sql
git add db/atlas.sql db/migrations/
git commit -m "что и почему поменялось"
git push            # ← сразу, не копить
```

`npm run db:dump` сам прогонит проверку целостности и откажется снимать дамп
с битой Базы.

## 4. Деплой

```sh
npm run deploy
```

Это всё. Скрипт сам:

1. соберёт Базу из дампа, если её нет;
2. соберёт выгрузку, проверит типы, соберёт приложение;
3. **проверит выгрузку** (`scripts/check_dump.py`): не пустая ли, не разошлась ли
   бесплатная версия с полной, нет ли узлов без карточки и связей в никуда;
4. **снимет слепок боя** в `.rollback/` — чтобы откат был всегда;
5. **покажет, что изменится**: сколько метрик прибавится, что переименуется,
   какие артефакты появятся или пропадут;
6. остановится, если из боя что-то пропадает, — пока не подтвердите ключом `--yes`;
7. зальёт и проверит, что бой отвечает.

Другие режимы:

```sh
npm run deploy -- --dry-run     # показать что уедет, ничего не трогая
npm run deploy -- --yes         # не спрашивать подтверждения
npm run deploy -- --no-build    # залить уже собранный dist/
npm run deploy -- --rollback .rollback   # вернуть прежний бой
```

### Ключи

Нужны `YC_KEY_ID` и `YC_SECRET` — сервисный аккаунт `static-deploy` в консоли
Яндекса. Положить в `app/.deploy.env` (шаблон — `.deploy.env.example`).
Файл в `.gitignore`, в репозиторий не попадает **никогда**.

### Откат

Перед каждой выкладкой в `.rollback/` ложится слепок боя. Вернуть:

```sh
npm run deploy -- --rollback .rollback
```

Возвращаются данные и `index.html`. Код приложения трогать не нужно: файлы в
`assets/` именуются по содержимому, прежний `index.html` ссылается на прежние
бандлы, а с бакета ничего не удаляется.

## 5. Две машины: как не затереть друг друга

Правда одна — дамп в репозитории. Отсюда правила:

1. **Перед правкой — `git pull` и `npm run db`.** Иначе вы правите вчерашнюю Базу.
2. **После правки — `npm run db:dump`, коммит и `git push` сразу.** Некоммиченная
   правка Базы существует в одном экземпляре, и её легко потерять.
3. **Перед деплоем — `npm run pull`.** Если бой ушёл вперёд, сначала разберитесь,
   чей он, и только потом выкладывайте.
4. **Конфликт в `db/atlas.sql` не разрешается силой.** Не `--ours`, не `--theirs`:
   обе стороны — чья-то работа. Разговор, потом правка.

Так было 22.09.2026: копий Базы оказалось две, и в одной было дерево, которого
не было в другой. Пока это не заметили, любая сборка «не с той» копии снесла бы
чужую работу целиком.

## 6. Автоматический деплой (CI)

`.github/workflows/deploy.yml` собирает и выкладывает на каждый пуш в `main`.

**Сейчас он не заливает в бакет:** шаг стоит под условием `if: env.YC_KEY_ID != ''`,
а секретов в репозитории нет. Чтобы включить, добавить в GitHub → Settings →
Secrets and variables → Actions:

* `YC_KEY_ID` — идентификатор ключа сервисного аккаунта,
* `YC_SECRET` — сам ключ.

⚠️ **Проверьте перед включением**, что `npm run build` в CI проходит и
`scripts/check_dump.py` не ругается: синк идёт с `--delete`, то есть лишнее
с бакета удаляется. Проверка выгрузки в workflow для того и стоит.

История: с 28.08 по 22.09.2026 CI падал **каждый** пуш — 18 раз подряд.
Сборка звала `../content/db/build_app.py`, то есть файл с одной конкретной машины,
которого на сервере GitHub нет и быть не может. Письма о падении приходили месяц.
Сейчас сборщик лежит в репозитории (`scripts/build_app.py`), и CI собирается сам.

## 7. Скрипты

| Команда | Что делает |
|---|---|
| `npm run db` | дамп → рабочая База |
| `npm run db:dump` | рабочая База → дамп (с проверкой целостности) |
| `npm run db:check` | целостность Базы + не разошлись ли База и дамп |
| `npm run gen` | База → выгрузка `public/data/*.json` |
| `npm run dev` | выгрузка + стенд на vite |
| `npm run build` | выгрузка + типы + сборка `dist/` |
| `npm run pull` | что сейчас в бою и чем отличается от моего |
| `npm run deploy` | проверка, слепок, сборка, выкладка |
| `python3 scripts/check_dump.py <папка>` | проверить готовую выгрузку |

`npm run gen:tree-static` и `npm run gen:legacy` — старые пути, конвейера
не касаются.

### Черновики дашбордов

`src/dash/drafts.ts` подключает листы из соседнего репозитория
`dashboards-methodology`, если он склонирован рядом с `app/`. Подключение
необязательное: нет репозитория — черновиков просто не будет, сборка пройдёт.
Поэтому локальная сборка их содержит, а сборка в CI — нет. Разницы в бою это
не даёт: дашборды и так видны только на localhost или по `?dash=`.

## 8. Что проверить, если что-то сломалось

| Симптом | Куда смотреть |
|---|---|
| `npm run dev` падает | Базы нет → `npm run db` |
| В приложении старые тексты | выгрузка не пересобрана → `npm run gen` |
| В бою не то, что локально | `npm run pull` покажет разницу |
| Деплой отказывается выкладывать | читайте, что написал `check_dump.py`: он называет беду словами |
| Каталог показывает не ту дату | дата берётся из `meta.updated`, а он ставится днём сборки |
| Бесплатная версия разошлась с платной | признак правки мимо Базы; починка — `npm run gen` из Базы |

## 9. Правила, на которых всё держится

1. **Источник правды — База.** Выгрузка, стенд и бой — производные. Правка,
   внесённая мимо Базы, живёт до следующей сборки и разводит версии.
2. **Карточка метрики сквозная.** Одна метрика — один текст на все её места,
   во всех артефактах и в обеих выгрузках.
3. **В каталоге видны все артефакты.** Платное неоплатившему показывается
   с замком, а не прячется. Урезается содержимое, не витрина.
4. **Ключи — только в `.deploy.env` и в секретах GitHub.** Не в коде, не в дампе,
   не в истории.
5. **Списки оплативших не выкладываются.** Боевой `payment/paid.json` ведёт сайт,
   он в корне бакета; деплой его пропускает намеренно и проверяет себя дважды.
